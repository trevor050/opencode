Run a ULMCode operation audit and write durable audit artifacts.

Use this before a long-running operation is handed to a human, after an interruption, or when a final handoff claims to be ready. The audit combines the restart health check from `operation_resume` with final handoff linting from `report_lint`, then writes machine-readable and markdown audit files under `.ulmcode/operations/<operation-id>/deliverables/`.

The audit is intentionally strict by default. It requires the operation to be in `handoff/complete`, requires operation-plan, report, rendered deliverables, and runtime-summary artifacts, checks credential-vault handoff proof when the plan depends on provided/authenticated credentials, and returns recommended follow-up tools for every gap. For substantial reports, pass the same outline, PDF, and finding gates you used with `report_lint`, including `requireOutlineBudget`, `minOutlineTargetPages`, `minPdfPages`, `requireOutlineSections`, and `requireFindingSections`.

If the audit reports incomplete operation lanes, missing lane proof, or unmet coverage lanes, use `operation_run` to complete or repair the named lanes before editing reports, plans, goals, or coverage files. Report prose changes cannot satisfy lane-state blockers.
