Manage operation-scoped credentials for authorized testing.

Use this when the operator agrees to provide test credentials, API tokens, or other authentication material for a ULM operation. Store credentials here instead of chat, operation memory, evidence, reports, command text, or task metadata.

Actions:

- `create`: store or update one credential. Provide a clear label, optional username/password/url/tags/notes, and keep notes scoped to authorized use.
- `list`: show credential handles and metadata with secret values masked.
- `get`: show one credential handle with secret values masked.
- `delete`: remove one credential from the operation index and backing secret store.
- `materialize_env`: write a chmod 0600 env file for selected credentials. The output gives the env file path and variable names only. Source the env file in a supervised command instead of pasting secrets into command text.

Never echo raw credential values in messages, evidence, findings, reports, or operation summaries.
