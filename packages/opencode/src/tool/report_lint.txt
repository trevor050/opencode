Audit a ULMCode operation before report handoff.

Use this before final reporting and after report edits. It checks whether the operation has a checkpoint ledger and whether findings are evidence-backed, validated, and report-ready enough for a defensible client deliverable. For long reports, use requireOutlineBudget=true so the report must satisfy the target_pages budget from reports/report-outline.md; set minOutlineTargetPages and minPdfPages for long unattended runs so a 20-hour operation cannot pass with a tiny outline or tiny rendered PDF; tune minOutlineWordsPerPage when the default 300 words/page is too high or low for the deliverable. Also use requireOutlineSections=true to require each Page Budget section to appear and carry enough substance, and use requireFindingSections=true plus minFindingWords to catch sparse individual finding writeups even when total word count is high. For final handoff, set finalHandoff=true so the operation must be complete, in handoff stage, and have the operation plan, rendered deliverables, and runtime summary.

Reports must not contain raw passwords, tokens, cookies, API keys, other secret values, private-life dossier details, destructive production exploit claims, sensitive data dumping, or persistence/backdoor claims. Use redacted credential IDs or vault-backed handles only.
