Advance a durable ULM operation graph.

Use this after `operation_schedule` to record lane lifecycle state. It reads the
persisted graph, auto-completes running lanes whose lane-complete proof
references real non-empty expected artifacts, syncs completed/failed background
jobs that include laneID metadata, and writes `plans/operation-run.jsonl`.

`operationID` may be omitted only when the current chat session is already bound
to an active operation by `operation_goal`, `operation_resume`, or another
explicit operation read. Fresh chats never inherit the newest operation from the
worktree; pass `operationID` explicitly when resuming from a new chat.

For long and overnight operations, run `operation_supervise` on startup, heartbeat, post-compaction, and pre-handoff cycles. If the supervisor returns `blocked`, `recover`, `schedule`, or `queue_work`, resolve that decision before blindly advancing the graph. `operation_run` advances lanes; it is not a substitute for supervisor review.

Modes:
- `advance`: scheduler-owned. Public tool calls return `wait` and do not mark a
  lane running; use `runtime_scheduler` or `runtime_daemon` to launch lanes.
- `complete_lane`: mark a lane complete and unlock dependent lanes.
- `skip_lane`: mark a lane skipped with a durable reason and coverage impact.
- `block_lane`: mark a lane blocked with a durable reason and coverage impact.
- `fail_lane`: mark a lane failed and preserve the blocker.

`complete_lane` requires a concrete `summary` plus explicit `artifacts`; report
and validation lanes should also include `evidenceRefs`. Empty directories,
missing files, absolute paths, and paths escaping the operation root are rejected.

`skip_lane` and `block_lane` are terminal states, not completion shortcuts. Use
`coverageImpact` and `releaseRequired` honestly; coverage-critical skips remain
handoff blockers unless the coverage contract explicitly allows them.

If a completion attempt returns blockers, repair the named artifact or evidence gap and retry `operation_run`. Do not hand-edit `plans/operation-graph.*`, `plans/coverage-contract.*`, or `lane-complete/*.json`; lane and coverage state are only valid when recorded by operation tools.

Lane workers should call only terminal modes (`complete_lane`, `skip_lane`,
`block_lane`, or `fail_lane`) before exiting. They should not call `advance` or
launch downstream lanes; the scheduler owns that handoff.

Use redacted credential IDs or vault-backed handles only. Never include raw passwords, tokens, cookies, API keys, or other secret values in summaries, artifacts, evidence refs, lane metadata, or blocker notes.
