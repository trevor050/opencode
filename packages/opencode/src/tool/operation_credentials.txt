Manage operation-scoped credentials for authorized testing.

Use this when the operator agrees to provide test credentials, API tokens, or other authentication material for a ULM operation. Store credentials here instead of chat, operation memory, evidence, reports, command text, or task metadata.

Actions:

- `vault_url` / `open_vault`: return the secure local credential-vault URL for this operation. `open_vault` also attempts to open it in the default browser when the app server URL is available, publishes a visible TUI progress card with a fallback URL, and always waits for the operator to click the vault's final Submit to agent button. Use this immediately after the operator says credentials are available, before asking for or handling any secret values. Use `vault_url`, not `open_vault`, when you only need the link without waiting.
- `review_status`: show the latest credential review submission. Use this after the vault submit step if you need to re-read the redacted credential records.
- `create`: store or update one credential. Provide a clear label, optional type/username/password/secret/url/target/tags/notes/rules, and keep notes/rules scoped to authorized use.
- `list`: show credential records and index metadata with secret values masked.
- `get`: inspect one credential record, or all records if `credentialID` is omitted, with secret values masked. This may include username, URL, target, tags, notes, rules, and a redacted raw-note preview for raw/bulk notes. Use `get` when the operator asks what the agent can see, but never reveal unmasked password/token/key/cookie values.
- `delete`: remove one credential from the operation index and backing secret store.
- `materialize_env`: write a chmod 0600 env file for selected credentials. The output gives the env file path and variable names only. Source the env file in a supervised command instead of pasting secrets into command text.

Never echo raw credential values in messages, evidence, findings, reports, or operation summaries.

When calling `open_vault`, pass only `operationID` and `action` unless there is a specific need for another field. Do not send empty optional strings or empty arrays. Do not set `waitTimeoutSeconds` to `0`; omitted or non-positive values use the normal operator wait. `open_vault` waits even if `waitForSubmit: false` is accidentally supplied. If `open_vault` is called twice for the same operation URL, the second call reuses the already-open vault window/card instead of opening another browser tab.
